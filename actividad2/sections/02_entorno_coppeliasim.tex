\chapter{Escenario CoppeliaSim}

La escena se construyo automaticamente con el script
\path{actividad2/coppeliasim/build_phase1_basic_scene.py}. Este generador carga
la escena base de la asignatura, elimina restos de pruebas anteriores, crea la
celda warehouse, ubica a R1 y B1, agrega shelves, mesas, obstaculos, piezas
visuales y embebe los controladores Lua finales. El mismo script ejecuta una
validacion headless y guarda los resultados en JSON.

\section{Bill como actor movil}

B1 no es un obstaculo estatico: representa una persona que se desplaza entre
estaciones de trabajo. El script \path{phase1_b1_walking_manager.lua} define
las estaciones WS1/WS2 como datos, publica la estacion actual, informa que
herramienta necesita y anima las acciones de tomar, trabajar y entregar. La
orientacion de Bill se calcula con:

\[
\theta_B = \operatorname{atan2}(y_{k+1}-y_k,\;x_{k+1}-x_k)
\]

De esta forma Bill camina orientado hacia la direccion de movimiento. Cuando
esta en una mesa, su yaw se orienta hacia la superficie de trabajo para evitar
que parezca trabajar de lado o de espaldas.

\section{Cola de tareas}

La cola de tareas se representa mediante senales internas de CoppeliaSim y una
maquina de estados en el controlador R1. El flujo completo se resume en la
Figura~\ref{fig:state-machine}. Las tareas no se disparan todas al mismo
tiempo: R1 espera a que Bill termine T1 y se desplace a WS2 antes de iniciar T2.

\section{Piezas visuales}

Para evitar cubos genericos, T1 y T2 se construyen como conjuntos de primitivas:
T1 parece una pieza mecanizada con placa, nervios, boss central y pernos; T2
parece una placa compuesta/electronica con railes, conector y capacitor. Esto
mejora la lectura visual y permite que las capturas del escenario comuniquen
que se estan manipulando herramientas/piezas reales, no marcadores abstractos.
