\chapter{Funcionamiento operativo}

El flujo diario se diseña para que el robot apoye al operario sin introducir pasos innecesarios. La operación normal sigue la secuencia siguiente:

\begin{enumerate}
  \item Planificación de misión. El supervisor, la estación o el planificador genera una misión de entrega, retorno o inspección.
  \item Carga de kit o herramienta. El personal de logística coloca el material en el módulo portacargas del AMR.
  \item Lectura RFID/QR. El robot valida identificadores de kit, herramienta, orden y destino.
  \item Navegación hasta estación. El AMR calcula ruta, evita obstáculos y ajusta velocidad según zona.
  \item Entrega. El robot se posiciona de forma lateral u orientada según la estación y avisa al operario.
  \item Confirmación. El operario confirma en HMI, tablet o lector QR; el sistema registra la transacción.
  \item Inspección FOD si aplica. El robot captura imagen de la zona o ejecuta una ronda definida.
  \item Retorno o nueva misión. El AMR devuelve útiles usados, va a carga o acepta la siguiente tarea.
\end{enumerate}

\section{Gestión de excepciones}

Si el robot detecta un obstáculo persistente, una lectura RFID incoherente, una zona bloqueada o una alarma de seguridad, la misión pasa a estado de excepción. La HMI muestra la causa y propone reintento, reasignación, llamada a operario o retirada del robot. Sin esta gestión, un fallo cotidiano puede bloquear pasillos, ocultar el estado real de una entrega o detener misiones posteriores.

\section{Datos generados para validación}

Cada misión genera datos que alimentan la validación posterior: identificador de robot, ruta prevista, ruta ejecutada, tiempo de espera, eventos de seguridad, lecturas RFID/QR, confirmación de entrega, incidencias FOD y resultado final. Estos registros permiten comparar la operación real con los escenarios simulados en CoppeliaSim y detectar desviaciones antes de escalar la flota.
